## Mistakes I made and what they taught
- `docker stop $(docker ps -a)` — fed the whole table (headers, image names) to `stop`. It errored on every word and stopped the container by accident when it hit the real ID. Fix: `-q` → IDs only. `docker stop $(docker ps -aq)`.
- `docker rmi $(docker images)` — same mistake, same accidental pass. Fix: `docker rmi $(docker images -q)`.
- `docker image prune` did nothing — without `-a` it only removes dangling (untagged) images. `docker image prune -a` removes every image no container uses.
- `docker rm` is for containers; images need `rmi`.
- `docker pull` only downloads. `docker run` pulls if needed, creates, and starts.
- Put `--name` after the image name → Docker tried to run `--name` as a command. Options go before the image; anything after it is the command.

Rule: run the inner command alone first (`docker ps -aq`) and look at what it prints before feeding it to anything. Same discipline as `aws ... --query --output text` before a loop.

## Things I can now read
- PORTS column: `host:port->container:port`. Left of the arrow = published on the host; right = where the process listens inside. `-p` is written the same way: `-p 38282:8080`.
- `EXPOSE` in a Dockerfile is documentation. `-p` is what publishes.
- Cleanup dependency order: stop → rm containers → rmi images. An image can't be removed while any container, even a stopped one, references it.
- Base OS of an image: `docker run <image> cat /etc/os-release` — override the default command.
- Image size is the base image. `python:3.14` ≈ 1 GB, `-slim` ≈ 150 MB, `-alpine` ≈ 50 MB. Alpine uses `apk` not `apt`; some Python packages fail to pip-install there. Slim is the safe first choice.

## Dockerfile I wrote
```
FROM python:3.14
WORKDIR /ContainerApp
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY handler.py .
CMD ["python", "handler.py"]
```
Why requirements before code: the install layer caches until requirements change; code changes don't re-run pip.
CMD vs ENTRYPOINT: CMD is a default you can override after the image name; ENTRYPOINT always runs and takes what follows as arguments.
